# 远川物流 · 仓内拣选与装车核验（FDE 全流程项目）

围绕“仓内拣选与装车核验”开展的 **FDE（Forward Deployed Engineering）** 全流程训练项目，从业务挖掘到运营迭代，共 9 个阶段、27 项任务。项目以合成业务场景为边界，仅使用本项目已采集的访谈事实（证据编号 `logistics-warehouse-f00` ~ `f55`）与待验证假设，每一步保留行动、结论、证据和责任人。

- **主问题提出人**：林亦舟 · 拣货员
- **共同提出人**：顾明岚 · 仓储经理
- **调查对象**：顾明岚（仓储经理）、林亦舟（拣货员）、唐映秋（波次计划员）、秦芮（WMS 工程师）、傅景（仓库安全主管）、叶书（配送站长）
- **模型**：deepseek-flash · 合成场景
- **证据基线**：`00-项目证据与需求发现报告.md`

## 已识别的核心瓶颈（业务挖掘阶段）

1. **取消订单在波次与装车之间缺少拦截** —— 取消单已进波次、拣完仍被装车、到站才发现（`f11`、`f44`），取消事件同步延迟 12 分钟（`f31`）。【P0，待验证】
2. **相似包装 SKU 错配** —— 相邻货位相似包装，新员工常拿错规格（`f10`），关键说明未随单据交接（`f14`）。【P0，待验证】
3. **装车复核提效与口径** —— 错发率/漏扫口径未固定则验收无法签字（`f00`、`f02`、`f42`、`f50`、`f53`）。【P0，待验证】
4. **AI 放行责任与审批矩阵未定** —— 上线前置条件（`f41`、`f22`）。【P0】
5. **数据口径与接口治理** —— 多系统状态无统一视图，故障期需人工兜底（`f30`、`f31`、`f32`、`f34`、`f35`）。【P1】
6. **跨岗交接与反馈闭环** —— 需绑定原业务编号与资料版本（`f23`、`f25`、`f54`、`f55`）。【P1】
