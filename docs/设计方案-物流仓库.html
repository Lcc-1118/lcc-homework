设计方案 · 仓内拣选与装车核验数智化协同助手
远川物流 · FDE 训练项目 · 版本 v0.1 · 2026-10-23
1 · 背景与目标
业务痛点（证据）
  • 取消订单已进波次、拣完仍被装车、到站才发现（f11、f44、f31）
  • 相似包装 SKU 相邻货位，新员工常拿错规格（f10、f14、f52）
  • 复核每日 7000 行，人工重复复核约 14 人时，耗时 35 分钟（f12、f00）
  • 错发率 1.8%、漏扫核查依赖人工，验收口径未书面固定（f00、f42）
转型目标
  • 错发率 1.8% → 0.5%；复核 35 → 20 分钟；漏扫为零（硬门槛）
  • 取消单、错配在装车前被拦截，异常一律转人工兜底
2 · 需求映射（REQ → 证据 → 协同助手模块）
需求证据协同助手模块
REQ-1 取消拦截f11、f44、f31cancel_interceptor（BLOCK + 转人工）
REQ-2 错配提醒f10、f14、f52mismatch_reminder（扫码解释+提醒）
REQ-3 口径核算f00、f42、f53metrics（错发率/漏扫核算）
REQ-4 审计留痕f41、f22、f45audit（建议+人工改动+签核）
REQ-5 数据校验f30~f35、f33validation（版本/时间校验+修复队列）
REQ-6 交接清单f23、f25、f54、f55handover（编号/版本/接手人/确认）
3 · 技术架构
纯 Python 3.10+ 标准库实现，CLI 三子命令（run / verify / metrics）；分层：
  • 入口层：main.py / __main__.py（argparse CLI，支持 python -m）
  • 核心层 core/：cancel_interceptor、mismatch_reminder、metrics、handover、pipeline（协同编排）
  • 工具层 utils/：validation（数据校验）、snapshot（故障快照去重）、audit（审计留痕）
  • 数据层：data/sample_wave.json（波次样本）、config/default.yaml（默认参数）
  • 测试：tests/test_core.py（11 项 unittest）
关键设计：只提示 + 人工确认，不自动放行、不写业务系统；异常路径统一转人工，审计可重建处理链。
4 · 流程设计
协同助手嵌入主流程：数据校验(REQ-5) → 取消拦截(REQ-1) → 错配提醒(REQ-2) → 复核漏扫核查 → 交接清单(REQ-6) → 审计留痕(REQ-4) + 口径核算(REQ-3)。 每个判断点（含取消单 / 相似SKU / 复核通过）均为「是→放行、否→转人工或返工」的确定性分支，人工确认后才继续。
5 · 安全边界与验收
边界（不做什么）
  • 不自动操作叉车、不做盘盈盘亏（f05、f52）
  • 不写入业务系统、不自动批准（f32、f41）
  • 取消单/缺依据/版本冲突/系统不可用 → 转人工（f44）
  • 不代替安全主管专业签核（f22）；高危操作遵现场规程（f40）
验收标准
  • 错发率 ≤ 0.5%（基线 1.8%）
  • 复核 ≤ 20 分钟（基线 35 分钟）
  • 漏扫为零（硬门槛）
  • 口径未书面固定前验收不可签字（f42）
  • 安全主管可否决上线，配送站长参与验收（f02、f04）
