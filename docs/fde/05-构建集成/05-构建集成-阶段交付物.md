## 行动 5.2 实现业务闭环 · 原型代码与版本说明

### 业务闭环（REQ-1 + REQ-2）

```
输入：波次 + 取消事件 + 货位表/SKU
  ↓
校验（f33）：主编号/版本对齐，歧义进修复队列
  ↓
规则：
  - 取消拦截（REQ-1）：检测波次中订单已取消 → 提示拦截 + 转人工
  - 错配提醒（REQ-2）：相似包装 SKU 扫码 → 显示解释 + 原记录 + 待确认字段
  ↓
输出：待人工复核的交接清单（不自动放行）
  ↓
人工确认（f15、f44）：波次计划员/拣货员核对
  ↓
审计留痕（f45）：业务编号/版本/事实引用/建议结果/人工改动/签核人
```

### 原型实现（Python 最小闭环示例）

```python
# warehouse_coop.py — 仓内拣选与装车核验 · 协同助手（合成原型）
class CancelInterceptor:
    """REQ-1 取消订单拦截：检出波次中已取消订单，转人工，不自动放行。"""
    def __init__(self, cancel_events, master_key="order_no"):
        self.cancelled = {e[master_key] for e in cancel_events}

    def check_wave(self, wave):
        cancelled_in_wave = [o for o in wave["orders"] if o in self.cancelled]
        return {
            "action": "block" if cancelled_in_wave else "pass",
            "cancelled": cancelled_in_wave,
            "human_review": True,          # 转人工（f44）
            "reason": "取消订单已进波次，需波次计划员核对（f15）",
        }

class MismatchReminder:
    """REQ-2 相似包装 SKU 错配提醒：扫码时显示解释与待确认字段。"""
    def __init__(self, sku_map, adjacency):
        self.sku = sku_map          # {sku: {spec, image_ref, version}}
        self.adj = adjacency        # 相邻货位相似 SKU 映射

    def scan(self, sku):
        similar = self.adj.get(sku, [])
        return {
            "action": "remind" if similar else "pass",
            "similar_skus": similar,
            "show_original": True,       # 显示原记录（f15）
            "show_pending_fields": True, # 显示待确认字段（f15）
            "auto_operate": False,       # 不自动操作叉车/盘盈盘亏（f52）
        }

def audit_record(req_id, biz_no, version, refs, result, human_edit, signer):
    """REQ-4/审计留痕（f45）。"""
    return {
        "req": req_id, "business_no": biz_no, "version": version,
        "fact_refs": refs, "result": result, "human_edit": human_edit,
        "signer": signer,
    }
```

### 版本说明

- `v0.1`（原型）：合成样本上实现取消拦截 + 错配提醒 + 审计留痕，不写业务系统、不自动放行。真实接口与模型评估待接续（见阶段 06）。

## 行动 5.3 实现异常与审计 · 异常处理与审计样例

### 异常处理

| 异常 | 行为 | 依据 |
|---|---|---|
| 接口中断 | 用带时间戳只读快照，界面显示“暂未更新”；重连按业务编号去重补齐，不反复触发 | `f35` |
| 数据歧义（主编号/版本不一致） | 进人工修复队列，不进自动推荐样本 | `f33` |
| 取消单 / 资料缺依据 / 版本冲突 / 系统不可用 | 转人工，标注触发原因、接手人、确认时间 | `f44` |
| 高危操作（叉车/危险品/冷链） | 遵循现场规程，不自动放行 | `f40` |

### 审计样例

```json
{
  "audit": [
    {
      "req": "REQ-1",
      "business_no": "WAVE-20261023-042",
      "version": "v0.1",
      "fact_refs": ["logistics-warehouse-f11", "logistics-warehouse-f31"],
      "result": "block_cancelled",
      "human_edit": "已由波次计划员唐映秋确认取消，移除该单",
      "signer": "唐映秋"
    }
  ]
}
```

> 审计要求：每次建议保留业务编号、资料版本、事实引用、建议结果、人工改动和签核人，能重建本次处理，不记录账号口令或不必要个人信息（`f45`）。试点原始资料按授权范围保存，评价记录保留 90 天（`f43`）。
